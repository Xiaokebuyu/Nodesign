01

项目全貌，也是指令的一部分

对话式工具里，用户与 Agent 之间只有一条文字通道。Nodesign 用一块双方都能读写的画布取代这条通道：用户在画布上做的每一件事，都会成为下一轮任务的上下文。

选中的对象、圈选的区域与当前视野随消息一并提交；产物之间的连线告诉 Agent 素材从哪里来、要用到哪里。

看产物、素材、板书与关系集中在一块画布上，不埋在对话记录里。

指圈选或选中目标，“这里”不需要再用文字描述。

排拖动、归类、连线标注“取材”“批注”“接着”“对照”“改自”。

改双击文字直接修改，改动与圈选一起交给 Agent。

02

Agent 的桌面、眼睛与黑板

Agent 直接在画布上工作：新建产物、放到相关内容旁边、连上取材关系，并在画布上检查自己的结果。Agent 只说明位置关系，具体坐标由系统计算。

需要拆解问题或规划步骤时，Agent 把计划写成板书。板书以文件保存，用户修改后，Agent 按修改后的内容执行。

桌面新建、摆放、归类、并排比较产物。

眼睛读取画布当前状态，截取产物在不同宽度下的画面。

黑板拆解问题、列出计划、比较方案，用户可以直接修改。

进度可见正在写入的产物、调用的工具与完成状态实时显示在画布上。

03

共同语境与项目记忆

双方读写同一块画布。用户的每次整理与修改，Agent 在下一轮都能读到；Agent 的每件产出都留在画布上，可以查看、修改与回退。

关系线记录取材与派生：哪张图用于哪个网站、演示稿依据哪份文档制作。Agent 跨产物工作时据此取材，无需重复说明背景。

跨会话延续项目决策、风格规范与偏好保存在工作区，新会话继续生效。

沉淀为 Skill满意的工作流程可以保存为 Skill，并发布到 Skill 市场。

对照

同一件事，两条路

左侧为对话式工具的做法，右侧为 Nodesign 的做法。

保留决策权Agent 处理重复任务，用户负责判断与取舍。

04 · 一次会话的六个步骤

从需求到可交付产物

Agent 先提供结构，确认后继续制作。

①描述需求输入目标和已有信息。
②确认结构Agent 提供结构，用户确认方向。
③选择工具Agent 选择图像生成、背景移除、页面制作或代码执行工具。
④生成产物产物放在相关内容旁边，并连上取材线。
⑤圈选修改圈选目标区域或连线说明取材，再输入要求。
⑥保存项目各版本持续保留，支持回退。

06

开放与扩展（规划中）

目标是让画布成为用户与多个 Agent、多个系统之间的协调层：各系统中的任务、文件与进度以卡片形式集中呈现在同一块画布上；Agent 通过 CLI、MCP 与浏览器操作这些系统；用户在画布上统一查看、比较与决策。

现状：本地版已提供 MCP 服务端，Claude Code、Codex 等 Agent 可读取 Nodesign 的运行状态。

命令行工具通过 CLI 在外部平台发起并跟踪后台任务，例如在 Kaggle 上提交 Notebook 运行。

浏览器协同用户编辑 Kaggle Notebook 等在线页面时，Agent 查看代码、定位问题并直接修改页面中的表单与代码单元。

MCP 服务连接 Blender 等创作软件，以及飞书文档、Notion 等文档平台。

开放画布工具Claude Code、Codex 等 CLI Agent 将产物与进度写入画布。

集中决策不同平台的产物在同一块画布上并排比较、批注与确认。
