# NoDesign

> **哪里错了圈哪里。生成、检查、反馈和修改，全程不离开同一张无限画布。**

[![npm version](https://img.shields.io/npm/v/%40xiaobuyu%2Fnodesign)](https://www.npmjs.com/package/@xiaobuyu/nodesign)
[![npm downloads](https://img.shields.io/npm/dw/%40xiaobuyu%2Fnodesign)](https://www.npmjs.com/package/@xiaobuyu/nodesign)
[![license](https://img.shields.io/npm/l/%40xiaobuyu%2Fnodesign)](https://github.com/Xiaokebuyu/Nodesign/blob/main/LICENSE)

NoDesign 是一张以真实文件为底座的 Agent Native 创作工作台。

告诉 Agent 你想做什么，它会在画布上创建网站、演示稿、Word 文档、图片和视频。你可以留在同一张画布上检查结果；发现哪里不满意，直接圈选、评论，或者在产物旁边发起讨论。

你当前的视觉焦点、选中对象及其组件信息会随消息一起交给 Agent。它会理解你说的“这里”究竟是什么，修改背后的真实文件，再回到画布继续检查。

```text
提出需求 → Agent 生成 → 画布检查 → 圈选反馈
        → 修改真实文件 → Agent 自检 → 原地继续
```

![在画布上圈选具体区域，Agent 获取目标上下文后直接修改](https://raw.githubusercontent.com/Xiaokebuyu/Nodesign/main/docs/demo-roundtrip.gif)

NoDesign 不只是把 AI 生成的结果摆到画布上，而是把生成、检查、反馈和修改组成的完整创作循环留在同一张画布里。

## 立即体验

### 本地版

需要 Node.js 22.16 或更高版本：

```bash
npx @xiaobuyu/nodesign
```

启动后配置至少一种模型接入方式：

- Claude 订阅或 Anthropic API
- OpenAI、DeepSeek、智谱、通义、OpenRouter
- Ollama 或其他兼容 OpenAI API 格式的模型服务

NoDesign 本身不收取订阅费，也不对模型调用加价。

项目文件和配置保存在本地。使用云端模型时，完成任务所需的上下文会发送给你配置的模型服务；使用本地模型（如 Ollama）时，数据可以完全留在你的电脑上。

### 在线体验版

暂时不想安装，也可以直接体验基础能力：

[https://nodesign.xiaobuyu.trade](https://nodesign.xiaobuyu.trade)

线上版提供免费模型和每日额度，部分依赖本机环境的能力暂未开放。

## 为什么整个创作过程可以留在画布里

### 哪里错了圈哪里

很多时候，问题并不是模型不会修改，而是它不知道你说的“这里”究竟是哪里。

在 NoDesign 中，你可以：

- 双击修改文字；
- 圈选一块区域并留下评论；
- 拖动和整理画布元素；
- 在不同内容之间建立「参考」「批注」「接着做」等关系；
- 在正在检查的产物旁边直接唤出 Agent。

当前视野、选中的目标、附近内容以及目标涉及的组件信息，会被整理为下一轮任务的上下文。

你不需要再截图并解释：

> 第二屏右边那个蓝色的块位置不太对。

直接圈住它，说一句：

> 这里太挤了。

这样就够了。

Agent 完成修改后，结果会回到同一张画布。你可以继续检查、追问或进行下一轮修改，不必在聊天框、预览窗口、编辑器和文件夹之间反复切换。

### Agent 能检查自己的结果

Agent 不只负责生成，也能主动检查自己做出来的东西。

对于站点，它可以：

- 获取桌面、平板和手机宽度下的页面截图；
- 读取浏览器控制台错误；
- 检查最终渲染样式；
- 检查字体是否正确加载；
- 提取滚动动效和关键动画帧；
- 根据检查结果继续修改。

![站点在桌面、平板、手机尺寸下的预览](https://raw.githubusercontent.com/Xiaokebuyu/Nodesign/main/docs/demo-viewport.gif)

如果连续修改后结果仍不理想，Agent 还可以邀请一个只读评审子代理，从第三方视角逐页检查问题。评审角色只负责找出缺陷，不会直接修改文件。

### 画布上的内容对应真实文件

画布不是文件的终点。

画布上的文件卡片对应磁盘中的真实文件，文件夹卡片对应真实目录。打开、重命名、归类和移动文件等操作会同步到项目工作区。

![打开文件夹、把卡片拖进文件夹、在两张卡之间建立关系](https://raw.githubusercontent.com/Xiaokebuyu/Nodesign/main/docs/demo-desktop.gif)

Agent 生成的网站、演示稿、Word 文档、图片和视频不会被锁在 NoDesign 的私有格式里。你可以：

- 在画布上继续检查和批注；
- 下载原始文件；
- 使用其他软件继续编辑；
- 修改文件后再交给 Agent 接着处理；
- 将项目发布或交付给其他人。

画布是一张连接文件、上下文和 Agent 的工作桌，而不是一个只能展示生成结果的容器。

### 不同产物可以在同一张画布上接着做

网站、演示稿、文档、图片、视频和参考资料可以同时摊在一张画布上，由同一个 Agent 连续处理。

例如，你可以：

1. 让 Agent 调研一个主题；
2. 将调研结果整理成 Word 文档；
3. 根据文档生成演示稿；
4. 从演示稿中提取宣传长图；
5. 根据同一批素材制作配套站点；
6. 圈出不满意的部分，让 Agent 原地修改。

Agent 可以掌握这些文件在项目中的位置，并在不同产物之间继续取材和工作，不必每换一种工具就重新解释项目背景。

![NoDesign 综合创作流程](https://raw.githubusercontent.com/Xiaokebuyu/Nodesign/main/docs/demo.gif)

### Agent 也可以自己寻找和分析参考

Agent 拥有自己的浏览器。你可以把一个网址交给它，也可以让它自己寻找参考内容。

它能够：

- 浏览和截图网页；
- 分析页面布局、配色和字体；
- 观察页面的内容分区；
- 检查滚动触发的动画与交互；
- 将有用的截图和素材放入当前项目；
- 根据参考内容继续生成站点、演示稿或其他产物。

在本地版中，浏览器可以保留登录状态。遇到验证码、登录确认或其他需要人工处理的步骤时，Agent 会暂停并请求你接管；处理完成后，它可以继续原来的任务。

### 思考过程也可以留在画布上

Agent 不只把最终产物放到画布上，也可以把中间思考过程摆出来。

它会画草图、写板书、在相关内容之间建立连接，说明自己的计划，或者把复杂问题拆成可以继续讨论的部分。

![拆解《雷雨》人物关系：生成角色、肖像与关系线](https://raw.githubusercontent.com/Xiaokebuyu/Nodesign/main/docs/demo-blackboard.gif)

板书本身也是真实文件，保存在项目的 `notes/板书/` 目录中。草图节点、连接线和板书文字都可以手动调整；修改之后，Agent 会继续使用更新后的内容。

![双击 Agent 写下的板书，在画布上原地修改](https://raw.githubusercontent.com/Xiaokebuyu/Nodesign/main/docs/demo-chalk.gif)

项目决策、风格记录和个人偏好不必只藏在聊天历史里。它们可以作为可见、可编辑的内容保留在工作区，也可以进一步沉淀成可复用的 Skill。

> 正在开发：将更多头脑风暴与对话分支迁移到画布。完成后，可以从不同阶段和节点继续提问、延伸或比较方案，而不必在一条越来越长的聊天记录中来回翻找。

## 它能帮你做什么

### 三个典型场景

- **制作作品集或落地页**  
  把参考图和文字素材放到画布上，告诉 Agent 你想要的风格。Agent 完成页面后，会检查桌面、平板和手机尺寸下的效果；你可以圈出不满意的位置继续修改，配置后发布到公网。

- **制作一份演示稿**  
  将照片、文字和参考风格放在画布上，Agent 生成分页幻灯。你可以直接查看每页效果、修改文字、圈选批注，最后导出 PDF 或 PPTX。

- **完成一个跨媒体内容项目**  
  将网站、图片、视频、演示稿和文档放在同一张画布上，由同一个 Agent 连续处理。不同产物可以共享已有素材、研究结果和风格上下文。

### 支持的产物类型

| 产物 | 文件格式 | 当前能力 |
|---|---|---|
| 演示稿、长图、海报 | `.html` | 支持 16:9、9:16、4:3 等比例分页，导出 HTML、PDF、PPTX |
| 作品集、落地页、小应用 | 带 `index.html` 的文件夹 | 桌面、平板和手机尺寸预览，整站 ZIP 导出，配置 Cloudflare 后发布 |
| Word 文档 | `.docx` | 生成标准 OOXML，不是将 HTML 修改后缀；支持页图预览、翻页和原件下载 |
| 图片 | 常见图片格式 | 图片生成、背景移除和素材处理 |
| 视频 | 常见视频格式 | 导入、预览和转码 |

## 配置

启动后，点击右上角齿轮进入设置页。

### 模型

设置页提供两类模型配置：

- **Claude 官方**：填写 Anthropic API Key，或通过 `nodesign login` 登录 Claude 订阅；
- **自定义接入**：从服务商预设中选择 DeepSeek、OpenAI、智谱、通义、OpenRouter、Ollama 等服务，并填写接口地址和密钥。

每个模型配置都可以运行连接测试，实际验证：

- 普通对话；
- 流式输出；
- 工具调用；
- 图片理解；
- Token 计数能力。

没有配置任何模型时，模型选择器会保持为空。

### 本机能力

启动时会自动探测：

- git
- Chromium
- LibreOffice
- poppler
- ffmpeg
- rembg
- 图片生成
- 搜索
- 发布能力

缺少依赖时，设置页会标明安装方法，对应工具也会明确显示为不可用。

### 其他设置

还可以配置：

- 搜索服务；
- 图片生成通道；
- Cloudflare Pages 发布；
- 命令沙盒；
- 自动权限检查。

配置文件存放在：

```text
~/.nodesign/.env
~/.nodesign/config.json
```

`.env` 用于保存密钥，`config.json` 用于保存模型插槽和其他配置，也可以直接编辑。

## 安全与隐私

每个项目都使用独立的工作区目录。本地数据默认保存在 `~/.nodesign/`，服务仅监听 `127.0.0.1`。

在支持的平台上，可以启用系统级命令沙盒：

- Linux：bubblewrap
- macOS：sandbox-exec
- Windows：当前暂不提供系统级命令沙盒

还可以启用自动权限检查，对文件上传、外部请求和其他敏感操作进行额外判断。

本地版默认不启用命令沙盒和自动权限检查，请根据自己的使用场景决定是否开启。

在 Windows 上，建议只打开你信任的项目，并在 Agent 执行以下操作前确认它的计划：

- 修改工作区外的文件；
- 安装软件或依赖；
- 上传本地内容；
- 执行其他可能影响系统环境的操作。

## 技术架构

- **前端**  
  React + Vite。无限画布的相机、命中检测、关系排布和产物能力系统为自研实现；`web/src/lib` 包含 46 个独立模块，几何计算、命中判定、导出格式等核心逻辑配有单元测试。

- **服务端**  
  Node.js ESM。Agent 会话以项目工作区作为执行目录，通过 54 个进程内工具操作文件、浏览器和不同类型的产物。

- **会话同步**  
  服务端维护会话状态，支持流式输出、断线恢复和多标签页同步。

- **模型兼容**  
  原生支持 Claude，并通过格式转换接入兼容 OpenAI API 的模型服务。无法匹配上游时直接返回错误，避免请求被发送到错误的模型服务。

- **产物系统**  
  网站、演示稿和 Word 文档通过统一的注册机制接入预览、导出和发布流程。新增产物类型时，通过同一注册入口接入相关能力。

## 开发

```bash
npm install && cd web && npm install && cd ..
npm run dev                 # 服务端，读 .env
cd web && npm run dev       # 前端
npm test                    # server 测试 + web 测试
```

> 注意：完整运行需要配置模型接入（Claude 订阅或 API Key）以及部分本地工具依赖。设置页会列出缺少的依赖和安装方法。

项目以 Vitest 测试套件作为发布前检查，server 和 web 合计 1,037 项用例，覆盖前后端契约、模块边界、权限能力表和关键用户文案。部分约束以静态测试固化，避免仅依赖注释和人工约定。例如：

- 前后端双份能力表逐项对账
- 权限判断必须通过能力表查询
- 用户可见文案的措辞检查
- 源文件行数棘轮

前端部署使用 `web/scripts/deploy.sh`（新分片加入、旧分片不删、`index.html` 原子替换）。服务端改动需要重启进程。
