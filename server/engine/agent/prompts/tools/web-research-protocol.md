# 上网调查协议（web_search 之后注入）

搜索结果是**候选清单**，不是答案。摘要给不了的东西：正文细节、数据表、代码、文档章节、评论区、PDF 正文、版面与配色、动效、点开才加载的内容。这些只有打开页面才拿得到。

## 第一次 web_search 之后的下一步

先打开至少一个候选，再回答用户。怎么打开看要拿什么：

- **读文字**（事实、文章、文档、数据、代码）：用 `WebFetch`，在 prompt 里写清要找什么、要原句、要站内链接。查资料默认走这条，快，也不占浏览器。它是内置工具，第一次用先 `ToolSearch("select:WebFetch")`。
- **开浏览器**只在这几种时候：借鉴一个站的版面、配色、字体、动效（`browser_navigate` + `browser_capture`）；页面要登录或过人机验证；内容要点击、翻页、「加载更多」才出来；`WebFetch` 读回来是空的（靠 JS 渲染）或被拦。能预判的多步装进一个 `browser_batch`。

## 按问题类型定最低深度

| 问题类型 | 最低深度 |
|---|---|
| 查一个事实（日期、人名、价格） | 摘要够；有出入就 `WebFetch` 一个页面核对 |
| 「它长什么样、怎么做到的」 | 浏览器打开并采集（capture：palette / fonts / skeleton / motion），再进两层内页 |
| 比较、选型、要数据 | 至少读 3 个来源（`WebFetch` 就够），把数字抽成一张表，标出来源 |
| 官方规范、API、文档 | `WebFetch` 文档页读到具体章节，引用原句；不用二手转述 |
| 一个人或作品的视觉脉络 | 浏览器：官方站 + 两个以上作品页，采集图和配色 |

## 翻到第三层的手

- 文字内容的内页：让 `WebFetch` 顺带列出站内链接，挑详情页、文档章节、单篇文章接着 `WebFetch`
- 看样子的内页：站内链接在 `browser_read` 的摘要里，挑案例页、详情页、定价页进去；首页是最套路化的一屏
- 列表页、「加载更多」、分页：`browser_find` 描述按钮拿 ref，`browser_computer` 点；滚到底再 `browser_read`
- PDF：下载后 `read_document` 读正文，不要只看搜索摘要
- 登录墙、验证码、人机验证：`browser_request_help` 请用户接手，不要绕

## 找到的东西要落纸

每个站一份 `assets/references/web/<站>.notes.md`，每条三样：URL、原句引用、它回答了哪个问题。写完再往下翻。没有笔记的深入等于没深入：翻到的东西没地方放，下一轮就丢了。

## 什么时候停

两个独立来源说法一致，或者已经拿到能直接用的东西（真实 CSS、数据表、原文章节）。在这之前不要回答，回答里只写笔记里有出处的内容。
