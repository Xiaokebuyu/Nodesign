# 黑板 RP 是什么

一场完全在画布上进行的角色扮演：正文直接落板书，状态住在板上，用户在板书上标注
来回应。这套**版面协议**来自一场真实 15 章会话的沉淀，照它跑能省掉一轮轮的试错。

**本 skill 只管版面。**分工按系统提示词的「你一个人演全场」节走：环境、情节、判定、
状态板、骰表，以及**台上每个人的台词**，全是你的笔（⛔ 这一版不派角色子代理）。
写谁的话之前先 Read 一遍他的 `角色/<名>/角色卡.md` 找回腔调。

隔壁三个包按需加载：**文风**→`story-voice`，**剧情技法/反公式/骰子判据**→`story-craft`，
**酒馆卡与预设导入**→`story-import`。

# 版面协议（六条，开场就按这个搭）

## 1. 章节是一条竖直线程

每拍正文一条板书：`write_on_board {text, tag:"章节", chain:true}` —— chain 自动接在
同 tag 上一条下面并画「接着」线，竖直往下长（纸 = 用户一屏）。**纸写满不会自动翻页** ——
排不下会被拒收，下一页你自己 `open_sheet` 规划。用户滚轮/翻纸就能回看整条故事。
⚠️ 串线程唯一正门是 chain（`near` 只画线不定位置，串不了线程）。
一拍别超过一屏；正文超过一个卡面（约 300 字）就**自己分段**：plan 里给每段开一个
空位（省掉 at 自动竖排），一段一条 write 填进去 —— 一段超了只拒那一段，不连坐。
现成长文（导入的文本）懒得手分时才用 `flow:true` 让机器按段落代拆。

## 2. 一拍 = 正文板书 + 选项板书

正文落完，紧跟一条选项板书（`reply_to` 本拍正文，同 tag），正文里用 nd:controls
围栏落成**真按钮**：

    ```nd:controls
    supersede: 章节选项
    - [A] 跟上去 -> 选A：跟上去，但保持距离
    - [B] 留在原地 -> 选B：留下，观察修女的反应
    - [继续] send
    ```

用户点选项是攒着（再点一次是取消，会真撤回队列）、点 [继续] 连同攒的一起进你下一轮
（消息形如【画布标注】板书「…」：选A…）。自由行动照旧走标注（在板书上写一句），
两条路都要在选项板书里提一句。选项写短、编号清楚。
**这不是第一拍的仪式，是每拍的义务**：玩家面前永远要有把手，他打出「接下来该怎么办」
就是你漏拍了。配方：一枚推进主线、一枚人际/私人、一枚剑走偏锋（合理但意想不到）。
⛔ 操作指引全走控件 —— 正文里不写「*（轮到谁…可以标注）*」式的括号舞台指令，
那每拍破一次第四墙。
`supersede: 章节选项` 那行是死期声明：下一拍的选项板一落，这拍的自动变灰 ——
每拍都写同一个组名，别的控件（背包/商店）不受影响。

## 2.5 控件不只是选项 —— 面板模式（发挥的地方）

nd:controls 是通用按钮：每枚 = 一条待发提示词。生命周期三档，按面板性质挑：

| 档 | 写法 | 给谁用 |
|---|---|---|
| 常设（默认） | 什么都不写 | 背包、商店、快捷动作 —— 全程要活着的 |
| 同组顶替 | `supersede: <组名>` | 章节选项、限时事件的当前一轮 |
| 定时 | `until: +30m` 或 ISO 时刻 | 倒计时抉择、限时商店 |

可以造的东西（都验证过语法，放开想）：
- **背包面板**（常设，进状态板组跟着走）：`- [用药水] -> 使用一瓶治疗药水`
- **商店**（进城落一张、离城 edit_board remove）：`- [买长剑] 30金 -> 购买长剑`
- **快捷指令条**（常设）：`- [骰] 我要主动检定 -> 我想对当前局面做一次主动检定，你定技能和DC`、
  `- [问] OOC提问 -> （OOC）`
- **限时抉择**：`until: +10m` + 正文写明倒计时后果

更新面板内容用 `edit_board set_text` 改那条板书（板书文件也认 —— 重写正文、
重算尺寸、线和标注全保留；只能改**自己写的**）。面板要跟着剧情走就归进 状态板 组吃
follow。**别把十个面板同时铺满** —— 常设面板 2~3 个（背包+快捷条）为宜，
场景性的（商店）用完就收。

## 3. 状态：数字住一张表，表住一条板书

⚠️ **2026-08-30 改了写法。**以前状态板是 `nodes:[PC卡, 当前场景, 明骰表]` 一组画布
节点 —— 那条路把字存进 `board.json`，而 `board.json` 在 gitignore 里：**用户回滚
项目时正文退回旧章、数字却停在新值**，agent 也 Read 不到那些字。现在分两件：

### ① 状态表（数字的家，一条独立板书）

开场落一条**独立的 chalk 板书**，`tag` 就叫 `状态表`，正文里一张两列表：

```
write_on_board {
  text: "## 状态\n\n| 键 | 值 |\n| --- | --- |\n| 好感度_苏绵 | 3 |\n| 时间 | 戌时 |\n| 体力 | 8/10 |",
  tag: "状态表", slot: "aside", staging: false
}
```

⛔ **必须用 `text:` 不能用 `nodes:`** —— `text` 才落成 `notes/板书/*.md` 文件
（进 git、用户能改、agent 能 Read、服务端能解析）；`nodes` 落的是画布原生节点。
⚠️ 给它划版位时留实数：一张带触发器围栏的状态表**约 500px 高**（真会话里给 460
被当场拒收）—— 开小了用 `edit_board replan` 调高，别废掉整页。

**这条板书全场只能有一条。**服务端按 `tag: 状态表` 找它，找到两条就拒绝写入并
点名两个路径 —— 它不猜该改哪一条。

**每拍改数字用 `set_vars`**：

```
set_vars { vars: { "好感度_苏绵": 5, "时间": "亥时" } }
```

它**只改表里那一格**，你写的说明文字、别的行、卡的位置一个字节都不动，卡高自动重算。
⛔ 别用 `edit_board set_text` 改数字 —— 那是重写整篇正文，等于让你把十几行不该变的
东西重新生成一遍，数字就是这么写丢的。

**数字的过去也是现成的**：`draw_trend {key:"好感度"}` 把这个键随拍数的走势画成
一条手绘曲线（数据来自工作区 git，每回合一点）——`set_vars` 之后再调一次它原地
长一格（用户拖过也认位置）。把它归进状态板组跟着走，玩家一眼看见关系怎么变的。

**改完不用记在脑子里**：表里的现值会出现在你**下一轮开头**的工作台状态里。
表被改坏（重复键、多张表、表没了）也会在那儿报警，不会静默消失。

**用户可以直接改这张表** —— 他在画布上双击就能编辑，改完就是新状态。这是特性不是
漏洞：状态是他和你共享的东西。

### ② 状态板（给人看的那几张卡，可选）

想在画布上摆得好看，另立一组卡（`tag:"状态板"`，`nodes:` 随意用），把状态表那条
板书也归进这一组，然后立一次跟随规则（**只立一次**）：

`edit_board { ops:[{ op:"follow", group_tag:"状态板", target_tag:"章节", side:"right" }] }`

从此每拍正文一落，整组自动挪到它右侧、锚线自动重指，你不用手搬。`#章节` 这会儿
还是空的没关系：规则先立着，第一拍一落自动接线并就位。用户拖过它也照样跟随
（他摆的**相对格局**会保留），要彻底停跟随用 `unfollow`。

⚠️ 这一组里的卡是**给人看的排版**，不是真相 —— 真相在①那张表里。两边别各存一份
数字，那是这条线上翻过最多次车的账。

### ③ 条件触发器：让服务端在该提醒你的时候提醒你

状态表那条板书的正文里可以写一段 ```nd:triggers 围栏 —— 挂几个条件，条件成立的
**那一拍**，服务端把你写的那句话端到你下一轮开头。

    ```nd:triggers
    - [好感度_苏绵 >= 5] once -> 她开始愿意主动找你说话了，这一拍给她一个开口的机会
    - [体力 <= 2 && 时间 == 夜] on_cross -> 体力见底又是夜里：这一拍必须有代价
    - [线索数 >= 3] once -> 线索够了，可以让他自己拼出真相
    ```

**语法（故意窄）**：`- [条件] 档 -> 要说的话`。`&&` 是唯一的连接词（全都成立才算
命中），没有 `||` 没有括号。比较符 `>= <= > < == !=`；**大小比较只对数字生效**，
比文字用 `==` / `!=`（写 `时间 >= 戌时` 会被明确报错，不会按字典序偷偷比）。

**两档，别选错**：

| 档 | 什么时候响 | 用在哪 |
|---|---|---|
| `once` | 第一次从不成立变成成立，之后退休 | 一次性的剧情钩子（好感度到了、线索够了） |
| `on_cross` | **每次**从不成立变成成立 | 会来回摆的（体力见底、天黑、进城） |

⛔ **没有"成立就一直响"这一档**，那会每拍注一遍，当天就变成噪音。

**三条要知道的**：

- **上膛不击发**：一条触发器刚写上去（或者服务重启过）的第一轮，就算条件当场
  就成立，也**不会**响 —— 它先记下当前状态。想立刻响就把值先落回去再改上来。
- **写错会被点名**：语法错、比较不了、键在表里不存在，都会在你下一轮开头写明
  「这条一直不会响」+ 原文。不会静默失效。
- **删一条就是编辑那一行**（`edit_board set_text` 或用户自己改）。每轮开头也会
  报「N 条挂着、M 条已退休」，你随时知道现在有几个钩子在等。

**挂触发器的时机**：埋伏笔的时候。你写下"如果她好感度到 5 就会主动开口"这个设计
的当下，把它挂上去 —— 而不是指望二十拍之后自己还记得。这正是这套东西存在的理由。

### ③ 明骰表分家

明骰表是**另一张表、另一条板书**（表头别用 `| 键 | 值 |`，用
`| 拍 | 检定 | DC | 骰 | 结果 |`）。⛔ 别跟状态表挤在同一条板书里 —— 一条板书里
出现两张 `| 键 | 值 |` 表，解析器会拒绝，`set_vars` 当场失败。

**状态是场务的正事，别让它烂在正文里。**数字变了板不变，用户就不信这块板了。

## 4. 在场人物栏

独立组 `tag:"在场人物"`，一个 NPC 一张卡，三行定式：好感 / 警戒 / 状态，用 `●●●○○`
五格条。人物上下场就 `edit_board` 加删卡；换场换整批时 `erase_group` 重画。

板上这张卡记的是**数值**；这个人的**人设**另有一份档案（`角色/<名>/角色卡.md`，
`cast_role` 写的那张）。够格（有名字、会再出现、用户会想单独跟他说话）就顺手写一张，
写他的话之前 Read 那份。两张卡各管一头，别混。

## 5. 明骰表

住在状态板里的一张 markdown 表，逐拍累积：`| 拍 | 检定 | DC | 骰 | 结果 |`。
骰子用 `roll_dice` **真投**（服务端随机，骰面同时直达用户屏幕）。
投骰过程写进正文（有仪式感），结果落表（可回溯）。
**怎么判、失败该换来什么** → `story-craft`。

## 6. 前情归档（十几拍后必然要做，别等画布撑不住）

章节链过 12~15 条：把旧章合并成一张「前情提要」板书（接在链头），全文归档进一个
`前情/第一卷.md` 文件，旧章节板书 `edit_board remove` 撤下（删除是软删，进回收站
`.nd/trash/`，捞得回来 —— 但归档文件先写好再撤，顺序别反）。

# 纪律

- **玩家画像持续沉淀**：留意他的口味（节奏快慢、吃哪种梗、雷点、对白密度），写进
  `记忆/玩家画像.md`，每场开演先扫一眼 —— 画像写「他吃什么」，不写剧情本身。
- 侧栏只说一句「第 N 拍上板了」，正文全在板上，别两头贴。
- 板书是 md：对白、分镜留白按文字节奏排，不要塞 sketch 节点（那是画图的）。
- 画场景小图（营地/圆桌/地形）用 shapes 的词汇表和算子省笔：`stencil` 有
  person/house/boat/sword 等十六词；**围一圈**用 `ring{n,cx,cy,upright:true}`
  （侧视图里帐篷/人有重力，不加 upright 会东倒西歪）；阴影面 `fill:'hatch'`。
- 一拍的板面动作（正文、选项、版面维护）同一回合连着发完，别摊到几拍；
  每一发看过返回再发下一发（拒收/余量的提示都在返回里）。
- 开场先 `read_user_view` 看他的屏幕，版面宽度按他的视口定；顺手
  `edit_board {ops:[{op:"chalk_edit", on:true}]}` 把「改板书」替用户打开 ——
  跑团里他随时要拖板书、改状态，别让他跟双击武装较劲。
