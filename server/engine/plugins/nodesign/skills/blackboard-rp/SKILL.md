# 黑板 RP 是什么

一场完全在画布上进行的角色扮演：**你既是 GM 也是执笔**，正文直接落板书，状态住在板上，
用户在板书上标注来回应。没有演出页、没有编排.yaml、没有第二条通路 —— 一切都是你的
工具调用。这套版面协议来自一场真实 15 章会话的沉淀，照它跑能省掉前人一轮一轮的试错。

跟 rp-craft 的分界：那条线是「搭台」（作品化、能反复进场、台词走专门通路）；这条线是
「开桌」（即开即玩、你亲自执笔、一切留在画布上）。用户中途想把这一场固化成作品，再转
rp-craft 不迟。

# 版面协议（六条，开场就按这个搭）

## 1. 章节是一条竖直线程

每章正文一条板书：`write_on_board {text, tag:"章节", chain:true}` —— chain 自动接在
同 tag 上一章下面并画「接着」线，竖直往下长，用户滚轮就能回看整条故事。
⚠️ 别用 `near` 串章节（那会往右侧爬，十几章拖出一万像素）。
一章 ≤1500 字；写得长就拆成「正文 + 补充」两条（补充 `reply_to` 正文）。

## 2. 一章 = 章节板书 + 选项板书

正文落完，紧跟一条选项板书（`reply_to` 本章正文，同 tag）：列出 2~4 个走向 + 允许
自由输入的提示。**用户直接在选项板书上标注回复**（"A"、"C+B"、一句自由行动）——
标注消息会带原文摘录和路径进你下一轮，从那里读他的选择。这条回路是全场最顺的交互，
护住它：选项写短、编号清楚。

## 3. 状态板：一个组，跟着最新章走

开场画一次：`write_on_board { tag:"状态板", layout:"column", staging:false, nodes:[PC卡, 当前场景, 明骰表] }`
（staging:false —— 状态板是常设件不是草稿），
然后立一条跟随规则（**只立一次**）：
`edit_board { ops:[{ op:"follow", group_tag:"状态板", target_tag:"章节", side:"right" }] }`
—— 从此每章板书一落，状态板自动挪到它右侧、锚线自动重指，你不用每轮手搬。
每章收尾只剩两步（一次 `edit_board`）：
1. `set_text` 更新变了的卡（内容变长没关系，下一步会重排）
2. `reflow {tag:"状态板"}` —— set_text 改高后整组重堆，防叠字
用户把状态板拖到别处后它就不再被自动挪（用户的座位优先），锚线仍会重指。

## 4. 在场人物栏

独立组 `tag:"在场人物"`，一个 NPC 一张卡，三行定式：好感 / 警戒 / 状态，用 `●●●○○`
五格条。人物上下场就 `edit_board` 加删卡；换场换整批时 `erase_group` 重画。

## 5. 明骰表

住在状态板里的一张 markdown 表，逐章累积：`| 章 | 检定 | DC | 骰 | 结果 |`。
投骰过程写进章节正文（有仪式感），结果落表（可回溯）。「自然 1 / 自然 20」值得在
正文里给一个镜头。

## 6. 前情归档（十几章后必然要做，别等画布撑不住）

章节链过 12~15 章：把旧章合并成一张「前情提要」板书（接在链头），全文归档进一个
`前情/第一卷.md` 文件，旧章节板书 `edit_board remove` 撤下（删除是软删，进回收站
`.nd/trash/`，捞得回来 —— 但归档文件先写好再撤，顺序别反）。

# 骰子判据（跑团的心脏，一句话版）

**失败换信息或代价，成功换新麻烦，两者都不许原地踏步。**

- 失败别写成「没成功」：写成错误结论说得很自信（然后别人看穿它）、失败落在表达上
  而不是结果上（最该先说的没说成）、代价是暴露了帮过你的人、账要到后面几章才结。
- 成功配一个新麻烦：拿到蜡烛 → 蜡烛开始倒计时；救下人 → 被救的说「你们不该救我的」。
- **给对手/NPC 也投一次骰**：一边的失败有了具体来源，场面自动变成博弈而不是判罚。
- 推动剧情的往往是失败骰 —— 别怕让玩家失败，怕的是失败没有后果。

# 文风校准（用户嫌「太 AI」时的第一动作）

不要靠「再自然一点」自己猜。**第一动作是要一份他认可的样本**：酒馆预设、一段他喜欢
的原文、一本书。拿到酒馆预设就 `read_tavern_json` 走 digest → fetch 文风相关条目
（几千字就能拿到完整的审美标准），把禁令转成清单再动笔。常见的雷（多数预设明令禁止）：
「不是A，是B」的转折句、一句一段满屏加粗、对白前后挂语气描写、正文用（）解释、
结尾抒情总结。

# 纪律

- 侧栏只说一句「第 N 章上板了」，正文全在板上，别两头贴。
- 板书是 md：对白、分镜留白按文字节奏排，不要塞 sketch 节点（那是画图的）。
- 一章的板面动作（正文、选项、状态维护）用一次 `board_batch` 跑完，别拆成七八次调用。
- 开场先 `read_user_view` 看他的屏幕，版面宽度按他的视口定。
