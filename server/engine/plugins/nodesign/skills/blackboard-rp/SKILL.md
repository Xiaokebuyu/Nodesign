# 黑板 RP 是什么

一场完全在画布上进行的角色扮演：**你既是 GM 也是执笔**，正文直接落板书，状态住在板上，
用户在板书上标注来回应。没有演出页、没有编排.yaml、没有第二条通路 —— 一切都是你的
工具调用。这套版面协议来自一场真实 15 章会话的沉淀，照它跑能省掉前人一轮一轮的试错。

跟 rp-craft 的分界：那条线是「搭台」（作品化、能反复进场、台词走专门通路）；这条线是
「开桌」（即开即玩、你亲自执笔、一切留在画布上）。用户中途想把这一场固化成作品，再转
rp-craft 不迟。

# 版面协议（六条，开场就按这个搭）

## 1. 章节是一条竖直线程

每章正文一条板书：`write_on_board {text, tag:"章节", chain:true}` —— chain 自动接在
同 tag 上一章下面并画「接着」线，竖直往下长，用户滚轮就能回看整条故事。
⚠️ 别用 `near` 串章节（那会往右侧爬，十几章拖出一万像素）。
一章 ≤1500 字；写得长就拆成「正文 + 补充」两条（补充 `reply_to` 正文）。

## 2. 一章 = 章节板书 + 选项板书

正文落完，紧跟一条选项板书（`reply_to` 本章正文，同 tag），正文里用 nd:controls
围栏落成**真按钮**：

    ```nd:controls
    supersede: 章节选项
    - [A] 跟上去 -> 选A：跟上去，但保持距离
    - [B] 留在原地 -> 选B：留下，观察修女的反应
    - [继续] send
    ```

用户点选项是攒着（再点一次是取消，会真撤回队列）、点 [继续] 连同攒的一起进你下一轮
（消息形如【画布标注】板书「…」：选A…）。自由行动照旧走标注（在板书上写一句），
两条路都要在选项板书里提一句。选项写短、编号清楚。
`supersede: 章节选项` 那行是死期声明：下一章的选项板一落，这章的自动变灰 ——
每章都写同一个组名，别的控件（背包/商店）不受影响。

## 2.5 控件不只是选项 —— 面板模式（发挥的地方）

nd:controls 是通用按钮：每枚 = 一条待发提示词。生命周期三档，按面板性质挑：

| 档 | 写法 | 给谁用 |
|---|---|---|
| 常设（默认） | 什么都不写 | 背包、商店、快捷动作 —— 全程要活着的 |
| 同组顶替 | `supersede: <组名>` | 章节选项、限时事件的当前一轮 |
| 定时 | `until: +30m` 或 ISO 时刻 | 倒计时抉择、限时商店 |

可以造的东西（都验证过语法，放开想）：
- **背包面板**（常设，进状态板组跟着走）：`- [用药水] -> 使用一瓶治疗药水`、
  `- [查看] 装备详情 -> 报一下当前装备和数值`
- **商店**（进城落一张、离城 edit_board remove）：`- [买长剑] 30金 -> 购买长剑`
- **快捷指令条**（常设）：`- [骰] 我要主动检定 -> 我想对当前局面做一次主动检定，你定技能和DC`、
  `- [问] OOC提问 -> （OOC）`
- **限时抉择**：`until: +10m` + 正文写明倒计时后果
更新面板内容用 `edit_board set_text` 改那条板书（按钮行照常重渲）；面板要跟着
剧情走就归进 状态板 组吃 follow。**别把十个面板同时铺满** —— 常设面板 2~3 个
（背包+快捷条）为宜，场景性的（商店）用完就收。

## 3. 状态板：一个组，跟着最新章走

开场画一次：`write_on_board { tag:"状态板", layout:"column", staging:false, nodes:[PC卡, 当前场景, 明骰表] }`
（staging:false —— 状态板是常设件不是草稿），
然后立一条跟随规则（**只立一次**）：
`edit_board { ops:[{ op:"follow", group_tag:"状态板", target_tag:"章节", side:"right" }] }`
—— 从此每章板书一落，状态板自动挪到它右侧、锚线自动重指，你不用每轮手搬。
每章收尾只剩两步（一次 `edit_board`）：
1. `set_text` 更新变了的卡（内容变长没关系，下一步会重排）
2. `reflow {tag:"状态板"}` —— set_text 改高后整组重堆，防叠字
用户拖过状态板也照样跟随 —— 他摆的**相对格局**会被保留（整组随新章平移）；
要彻底停跟随用 `unfollow`。

## 4. 在场人物栏

独立组 `tag:"在场人物"`，一个 NPC 一张卡，三行定式：好感 / 警戒 / 状态，用 `●●●○○`
五格条。人物上下场就 `edit_board` 加删卡；换场换整批时 `erase_group` 重画。

## 5. 明骰表

住在状态板里的一张 markdown 表，逐章累积：`| 章 | 检定 | DC | 骰 | 结果 |`。
投骰过程写进章节正文（有仪式感），结果落表（可回溯）。「自然 1 / 自然 20」值得在
正文里给一个镜头。

## 6. 前情归档（十几章后必然要做，别等画布撑不住）

章节链过 12~15 章：把旧章合并成一张「前情提要」板书（接在链头），全文归档进一个
`前情/第一卷.md` 文件，旧章节板书 `edit_board remove` 撤下（删除是软删，进回收站
`.nd/trash/`，捞得回来 —— 但归档文件先写好再撤，顺序别反）。

# 从酒馆搬进来（黑板线落点表）

用户扔来一份酒馆的东西（预设 .json / 角色卡 .png 或 .json / 世界书）：一律先
`read_tavern_json` 走 digest 看结构，**别用 Read**（真卡 7MB 起步）。PNG 卡直接
把 path 指向 .png，卡数据它自己解。

## 落点表（每样东西住哪，按「在场频率」定）

| 酒馆的东西 | 落点 | 为什么 |
|---|---|---|
| 预设启用条目（文风/规则） | 根 CLAUDE.md「演出规则」节 | 每会话确定性全量注入、压缩冲不掉、缓存前缀 —— agentic 线的"系统层冻结区" |
| 角色卡人设 | CLAUDE.md「人物」节（多角色时详表放 `角色/*.md`，核心三行进 CLAUDE.md） | 同上，人设不许漂移 |
| first_mes / 备选开场白 | 第一章板书直接开演 | 它是内容不是配置 |
| 世界书常驻条目 | `export_book` 落到 `世界书/常驻/` 后**人工挑十条以内**进 CLAUDE.md「世界观」节，其余降级成触发文件 | 常驻区是每轮的钱，只放真常驻 |
| 世界书触发条目 | `read_tavern_json {mode:"export_book"}` 一步落 `世界书/`（一条一文件，frontmatter 带 keys） | 触发式的东西不进常驻；几百条不许流经上下文 |
| 采样参数 / 破甲话术 / marker 占位 | 丢弃，照实告诉用户 | 这条通路没有对应物 |
| 跨会话演进事实（玩家偏好、剧情定案） | `记忆/`（你的 auto-memory） | 酒馆没有的东西，白送 |

## ⛔ 搬设定不搬引擎（世界卡的一半是程序）

大型世界卡（四方世界这类）常驻条目里一半是**酒馆前端的引擎件**：MVU 变量系统、
HTML 状态栏、CoT 框架、自定义回复格式、regex_scripts、tavern_helper。**这些一律
不搬** —— 平台有自己的对应物：变量/状态 → 状态板（follow 跟着走）；骰子 → 明骰表；
跨会话状态 → 记忆/；可点选项 → nd:controls 围栏。判据一句话：**这条是给读者看的
（搬），还是给酒馆程序执行的（不搬）**。挑常驻进 CLAUDE.md 时逐条过这一刀。

## CLAUDE.md 三节骨架（导入时写成这样；改它要用户点头）

```markdown
# <这场戏的名字>

## 演出规则（来自预设 <名>，启用条目已手拆）
<文风禁令清单 / 叙事规则 / 骰子规则>

## 人物
<人设正文；多角色时每人三行核心 + 指路 角色/*.md>

## 世界观（常驻十条以内；其余在 世界书/ 按触发词取）
<世界总纲级别的常驻条目>
```

## 用的时候（每章动笔前的固定两拍）

1. 拿本章要写的人名/地名/物件/事件 **grep `世界书/`**（触发词都在 frontmatter
   keys 和文件名里），命中就 Read 进来 —— 这就是酒馆世界书的关键词触发，你手上的
   Grep 天生就是触发器。宁可多 grep 一个词，也别凭记忆编设定。
2. 写完过一眼状态板要不要 set_text（连同 reflow，一次 board_batch）。

# 骰子判据（跑团的心脏，一句话版）

**失败换信息或代价，成功换新麻烦，两者都不许原地踏步。**

- 失败别写成「没成功」：写成错误结论说得很自信（然后别人看穿它）、失败落在表达上
  而不是结果上（最该先说的没说成）、代价是暴露了帮过你的人、账要到后面几章才结。
- 成功配一个新麻烦：拿到蜡烛 → 蜡烛开始倒计时；救下人 → 被救的说「你们不该救我的」。
- **给对手/NPC 也投一次骰**：一边的失败有了具体来源，场面自动变成博弈而不是判罚。
- 推动剧情的往往是失败骰 —— 别怕让玩家失败，怕的是失败没有后果。

# 文风校准（用户嫌「太 AI」时的第一动作）

不要靠「再自然一点」自己猜。**第一动作是要一份他认可的样本**：酒馆预设、一段他喜欢
的原文、一本书。拿到酒馆预设就 `read_tavern_json` 走 digest → fetch 文风相关条目
（几千字就能拿到完整的审美标准），把禁令转成清单再动笔。常见的雷（多数预设明令禁止）：
「不是A，是B」的转折句、一句一段满屏加粗、对白前后挂语气描写、正文用（）解释、
结尾抒情总结。

# 纪律

- 侧栏只说一句「第 N 章上板了」，正文全在板上，别两头贴。
- 板书是 md：对白、分镜留白按文字节奏排，不要塞 sketch 节点（那是画图的）。
- 一章的板面动作（正文、选项、状态维护）用一次 `board_batch` 跑完，别拆成七八次调用。
- 开场先 `read_user_view` 看他的屏幕，版面宽度按他的视口定；顺手
  `edit_board {ops:[{op:"chalk_edit", on:true}]}` 把「改板书」替用户打开 ——
  跑团里他随时要拖板书、改状态，别让他跟双击武装较劲。
