# 核心守则：先找到那一份，再做整套

一个 deck 做砸，几乎不是排版技巧的问题，是**没跟用户对上他想要的样子就开始铺量**。
铺完再改等于重做，用户也说不清哪里不对，只会说"感觉不是这个味道"。

所以顺序永远是：

**命名 → 试作 → 给看 → 改 → 用户说"就这个" → 锚定 → 铺开整套**

命名是把他嘴里的形容词换成一个真实存在的风格名（下面单独一节），它决定了试作
往哪个方向做；跳过它直接试作，等于拿模型均值去猜他的心思。

试作阶段一次只做一页（通常是封面，或者最能代表调性的那页），做真的、可看的，
不是描述。用户看着实物给反馈，比看你写"暖调克制风"准一个量级。
方向没定之前不要往后铺页，铺了就是在给自己制造返工。

## 形态从一个问题长出来

风格之前还有一层：**这份东西在什么场合被谁消费，看完要发生什么？**
关键分叉是"讲的时候有没有人在场"——有人讲，页面是讲话的背景板，字少图大
节奏归讲的人；没人讲，页面自己要把话说完，密度和完整性归页面。
答案定了，页数、密度、比例、语气自己长出来。

几个常见答案长出来的样子，当参考不当分类：

- 「投资人听完想约下一次」→ 少字大图，一页一击，节奏有起伏，结尾收在行动上
- 「自己读完就得懂」→ 信息完整优先，页可以密，图表带完整标注，读感像文档
- 「课堂上跟着讲」→ 概念逐步展开，一页一步，前后页强连贯
- 「一张图发出去」→ 海报 / 竖版长图，单件作品，全部力气砸在一屏里

不在这几种里的（婚礼流程册 / 菜单 / 展签……）照样用那个问题现推，别硬套。
brief 里读不出场合就问一句 —— 这一步答错，风格做得再好也是给错的东西抛光。
比例四档的选择（prelude 硬规则）就该从这里的答案顺下来，而不是单独拍。

## 先给风格一个名字

形态定了、动手之前，还差一步：**把他脑子里那个感觉，翻译成一个现实中真实存在的
风格名**。

用户说得出的是感觉（"高级一点""有质感""别太商务"），你能执行的是名字。形容词
只会把你推向模型均值 —— "温暖克制的现代感"做出来就是那张 AI 默认页；"拼贴"
做出来立刻就有样子，因为它在现实里有实物、有做法、有可仿照的对象。反默认清单
说的是**别去哪**，风格名说的是**去哪**，这两件是一对。

这一步的产出：**一个用户点过头的名字**。

1. 从他的话里抠特征：他提到的东西、举的例子、否掉的东西，以及他做的这件事本身
   （同人本宣传图 / 歌词视觉页 / 作品集主页各有自己的风格谱系）
2. 翻译成 2-4 个候选名字（词典在下面，那是你的词汇量）
3. `AskUserQuestion` 给他挑：label 就是名字，`preview` 放一张 240×140 的 HTML
   小样（全 inline style，演示这个风格的字体 / 配色 / 版式关系）。小样比找张照片
   来得准 —— 照片是别人的作品，小样是**你打算怎么做**。
   ⚠️ 别把网上的图片网址塞进 `preview`：只有以 `.png/.jpg/.webp` 结尾的地址才会
   渲染成图，其余会**静默退成一行网址**，用户看到的就是一串链接
4. 他点中的名字就是锚，试作**照着这个名字的做法做**，不是凭形容词现编

⚠️ **不要为了"理解风格"去搜图**。Bauhaus、拼贴、risograph 这些名字模型脑子里本来
就有，搜一轮只是白烧时间和上下文。搜图是留给**你确实不认识的具体东西**：用户点名的
IP、角色、真人、某个具体产品型号、小众品牌 —— 那种情况才走
`web_search { include_images: true }`，把图喂 `generate_image` 的 `referenceImages`
当锚（完整的来源策略在首次生图时注入的 cookbook 里）。

三条红线：

- **形容词不是名字**。"温暖克制的现代风"是三个形容词摞在一起，不是锚。
- **自造词作废**。名字得是**公认的** —— 你说得出它的实例、指得出现实里的作品。
  "新中式赛博风"这种当场拼出来的词没有共识，写进锚里等于没锚。
- **别把词典摊开当菜单让用户选**。名字是从他的话里翻译出来的；他该看到的是
  2-4 个带小样的候选，不是一张风格大全。摊开菜单就退回模板思维了。

他已经点了名字（"我要拼贴风"）的，跳过前两步直接进试作；直接甩了参考图的，
读图读出那是什么风格、跟他确认一下名字，再进试作。

### 翻译词典 —— 你的词汇量，不是给用户的菜单

第三列才是这张表的价值：名字得能立刻落到代码上，否则做出来的还是"那个名字的
均值版"。表外的风格多得是，照样现推。

| 他可能这么说 | 名字 | 落到代码上是哪几条 |
|---|---|---|
| 手作感 / 有温度 / 像手账 | **拼贴 collage** | 微旋转 -3°~3°、`filter: drop-shadow` 不用 box-shadow、白边、元素骑线或探出边缘、纸纹底 |
| 干净 / 专业 / 别花哨 | **瑞士国际主义 / 网格派** | 单一无衬线字族、模块化栅格且元素严格落格、非对称排布、左对齐不居中、双色以内 + 大面积留白（具体色值仍走色彩节，别真用纯黑） |
| 像杂志 / 有编辑感 / 高级 | **杂志编辑风 editorial** | 衬线大标题 + 无衬线正文、通栏与窄栏混排、首字下沉、图片出血、栏目名页码这类细节排版 |
| 复古 / 怀旧 / 像老印刷 | **risograph / 活版** | 2-3 套色叠印、故意错位、纸纹噪点、低饱和荧光色 |
| 科技 / 未来 / 赛博 | **终端 / HUD**（不是紫蓝渐变） | 等宽字、扫描线、坐标刻度与标注线、深底上单一荧光色 |
| 可爱 / 二次元 / 谷子 | **贴纸风** | 圆角厚白边、高饱和、硬投影、元素堆叠遮挡 |
| 安静 / 留白 / 想让人慢下来 | **日式极简** | 行高字距都拉开、正文宽收窄、近乎无彩色、层级靠留白不靠字号 |
| 有冲击 / 反叛 / 别装精致 | **粗野主义 brutalist** | 系统默认字体、纯色硬边框、零圆角零阴影、故意的不对齐 |

## 试作怎么做

- **缺什么就现做参照**：主体或隐喻说不清时 `generate_image` 出一两张看看。
  看得见的东西才对得齐。
- **一次给 2-3 个方向，不要一个**：单个方案用户只能说好或不好，并排才能说出
  "左边的字，右边的颜色"。名字上一步已经定了，所以这 2-3 个是**同一个名字的不同
  解法**（拼贴：纸质手账感 / 杂志剪报感 / 拍立得散落感），不是三种不同风格 ——
  摆三种风格等于推翻他刚点过的锚。差异用 `preview` 字段让用户直接看（语法见 prelude）。
- **命名那轮没收敛就别硬收**：他两个候选都想看，就跳过选名字，两个候选各做一份
  真试作、标签带名字并排给他挑。真稿的判别力比 240×140 的小样高一个量级，多花的
  那点时间在这儿是值的。
- **快**：试作页允许糙，占位文字、灰块占图都行，它的任务是把风格说清楚，不是交付。
- **一轮不够就再来一轮**，用户的话往往是"再冷一点""字太挤"这种相对量，
  改完再给看。这几轮是整个项目最值的时间。

用户说"你看着办"通常是描述不出来，不是没偏好。这种情况直接做两个方向给他挑。
明说赶时间的，用模板兜底起步，但仍然要先给一页看过再铺。

## 锚定

用户点头之后，把这一份固化下来，它就是后面所有页的基准：

- `<style id="design-tokens">` 的 `:root` 整组写死（色号、字号、字体链）
- 落锚进长期记忆：写一条 `type: project` 记忆（名字打头，如「风格锚 = 拼贴」，
  取值写进正文："纸纹底 + 微旋转 + 白边 + 手写体标注 + 一点樱桃红"）；项目级
  定案还该进根 `CLAUDE.md` 的「风格档案」节（用户点头后）。参照图留在
  `assets/references/` 别删 —— 后面几页跑偏时靠它回锚

锚说不出名字，说明还没定下来，回去再试一轮。

## 铺开

每页只回答一个问题：**这一页用锚的语言怎么说这件事**。

- 一页一个核心句，一个视觉主角。盖住其他文字只看它，讲不清就砍。
- 相邻页拉开节奏：满与空、图与字。整套下来页页同构就成了 PDF。
- 说不出用意的装饰，删。
- 中途觉得锚不对，停下来跟用户说，不要一页一页悄悄漂过去。

写到第 8 页的用色和字体决策，应该跟第 1 页出自同一个锚。

## 页内系统（锚定时一起固化进 tokens）

**字号跨度敢拉大**。deck 是一屏一屏看的，不是凑近读的 —— 核心句 72~160px、
正文 20~28px、注脚 14~16px，跨度小了整页就平。层级用两三个维度做足
（字号 + 字重 + 颜色深浅），别每级只放大一点。

**间距用一套刻度**（如 8 的倍数），页内块间距明显大于行间距 —— 一页的"呼吸感"
靠块间留白，不靠缩小字号腾地方。中文正文行高 1.6~1.8（deck 比网页可以略紧），
字距 0.02~0.04em（大标题 0 到 -0.01em），字体链 latin 段后必须跟 CJK 段（`'PingFang SC', 'Noto Sans SC'`），
细字重（300 以下）别用在小字号汉字上。

**色彩：一个主色 + 一套中性灰梯度**。主色小面积用（强调词 / 数据 / 细线）才有
分量，整页铺主色是海报的事。文字别用纯黑纯白 —— 深色往主色方向偏一丝，
整套 deck 的温度就是这么来的。灰要成梯度（正文 / 次要 / 注脚 / 线），全套复用。

**图像**：全幅大图压字只压文字落脚的局部（详见 patterns/image-led-cover.md）；
`generate_image` 出的主体可以 `remove_background` 抠成透明叠层用 —— 人物半身像
出血压边（patterns/portrait.md）、物件散落在大字周围，比规规矩矩放在框里生动
一个量级。抠图记得 `filter: drop-shadow(...)` 贴地，别用 box-shadow（会给透明区
画矩形影子）。

**动效是调味**：模板里 gsap / framer-motion 都在，但一套 deck 一两种动效语言
就够（进场淡入 + 一处强调动画）。每页都动的 deck 像广告牌，不像陈述。动效做完
自己看：`screenshot_canvas { frames:[…], trigger }` 出胶片条（2~30 格），数值级判断上
`trace_motion`，靠什么在动用 `artifact_motion` 对账。

## 反默认清单

下面这些是 AI 视觉的统计均值 —— 出现任何一条，说明那里**没有做设计决策**，
只是滑进了模型的默认输出：

| 均值 | 它替代掉了什么思考 |
|---|---|
| 等高卡片网格（3-4 张同尺寸平铺） | 这几件事真的同等重要吗（不等重就左大右小 / 单 hero + 注脚） |
| emoji 当视觉主角 | hero 位到底该放什么：大字 / 真图 / 数据 / 形状 |
| 浅色 wash 渐变 + 浮动圆点 | 背景在为哪句话服务 |
| 每页顶一个彩色 chip 当 label | 章节感要不要独占一页转场（大编号 + 一句概括） |
| 相邻页同版式复用 | 节奏：满↔空 / 图↔字 / 静↔动，翻页要有呼吸 |

铺完扫一眼，命中的地方回去把被跳过的那个问题答了 —— 答案可以恰好是默认形态，
但要是选出来的，不是滑出来的。锚存在的意义之一，就是让这些默认无处可套。

## 修改进来时

先分清是**锚内**还是**动锚**：换字号、改文案、换图、调间距是锚内，直接做；
换主色、换字体气质、"改冷酷一点"是动锚。动锚时把话说到名字上 —— "现在是拼贴，
你要的听着更像粗野主义，我把已有页一起对齐过去？" 比"要不要改风格"具体得多，
用户也才知道自己在换什么。确认后更新锚的落档并全局传播，不留一半旧一半新。
分不清就按动锚处理。

## 板书（交稿纪律）
做完这一轮的东西，写一条板书连上它（`write_on_board near=那张卡` —— near 画「说的是它」那条线，字落在当前纸上）：这版是什么 / 为什么这么做 /
看哪里。改了几处就写几条要点，一条说一件事。同一件东西出了新版本，画一条「改自」线
（`edit_board` add_edge derives-from）；有参考来源画「取材」。用户在你的板书上标注了，用
`write_on_board reply_to=` 接在那条下面回。多步任务先 TodoWrite 列步骤 —— 步骤清单会自动上板、
每步的产物自动连过去。
