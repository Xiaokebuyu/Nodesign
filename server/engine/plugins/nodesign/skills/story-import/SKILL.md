# 第一动作

**`read_tavern_json` 走 digest 看结构，⛔ 别用 `Read`** —— 真卡 7MB 起步，
一次 Read 能吃掉半个上下文。PNG 卡直接把 path 指向 `.png`，卡数据它自己解。

**把整份读完再动手**。条目多就分几次把 entries 全拉下来 —— 落点判断靠的是内容，
不是标题，只扫名录就开工必错。

# 判据：这段内容说的是「这个人是谁」，还是「这个故事该怎么讲」？

前者进人物档案，后者进项目 CLAUDE.md 或文风。**这一步搞错，后面全错。**

第二个判据同样重要：**原样 cp 还是改写适配**。能原样用的原样搬 —— 尤其用户为
solo 挑的对象卡，那个声音是他自己挑的，转写一遍等于把它洗掉。只有跟平台机制
打架的部分（引擎零件、输出格式、越狱框架）才动手拆改。

# 落点表（按「在场频率」定，不按类型定）

| 酒馆的东西 | 落点 | 为什么 |
|---|---|---|
| 预设里的文风/叙事规则条目 | **演出显示器那条路**：整份 JSON 原样放进 `<戏>/预设/<名>.json`，机器拆成开关，玩家开场页自己勾（默认给 Izumi 那套）；**你自己代演**时才拆进根 CLAUDE.md「台面规矩」节 | 预设是给写手的规矩不是给某个人物的；拆成开关比抄进提示词能让玩家随时改 |
| 角色卡人设 | `角色/<名>/角色卡.md`（`cast_role` 写），核心三行进 CLAUDE.md「人物」节；卡里"由玩家决定是否启用"的条目写进卡的 `## 可选` 一节（一条一行 `- [ ] 名 — 说明`），显示器开场页画成开关 | 人设不许漂移；玩家自选的东西别替他定 |
| `first_mes` / 备选开场白 | 第一拍板书直接开演 | 它是内容不是配置 |
| 世界书常驻条目 | `export_book` 落 `世界书/常驻/` 后**人工挑十条以内**进 CLAUDE.md「世界观锚」 | 常驻区是每轮的钱，只放真常驻 |
| 世界书触发条目 | `read_tavern_json {mode:"export_book"}` 一步落 `世界书/`，一条一文件、frontmatter 带 keys | 触发式的不进常驻；几百条不许流经上下文 |
| 采样参数 / 破甲话术 / marker 占位 | 丢弃，照实告诉用户 | 这条通路没有对应物 |
| 跨会话演进的事实（玩家偏好、剧情定案） | `记忆/` | 酒馆没有的东西，白送 |

# 角色卡 → 一份人物档案

| 卡里的字段 | 去哪 |
|---|---|
| `name` | `cast_role` 的 `name`（中文名放这；`id` 另取 ASCII slug） |
| `description` / `personality` | 档案主体 |
| `mes_example` | 档案里的语气样本，挑两三段别全抄。**这是你模仿他说话的依据** |
| `scenario` | **不进档案**，当开场场景写进第一拍（场景会变，人设不会） |
| `first_mes` | 当第一拍的板书写出来 |
| `character_book` | `export_book` 落成世界书文件，用到时 grep |
| `system_prompt` / `post_history_instructions` | **先判断**：通用越狱／输出格式 → 丢；这个角色特有的铁律 → 并进档案 |

一张卡里写了好几个 NPC 是常事：**拆成好几份档案，别挤进一份。**

# 预设 → 不是给某个人物的

预设里那堆条目绝大多数是给**你**的：叙事规矩、文风、节奏、输出格式。
⛔ 别把整份预设塞进某个人的档案 —— 那会让一个 NPC 背着一整套导演手册说话。

**走演出显示器时不用你拆**：把原 JSON 放进 `<戏>/预设/<名>.json`，机器按 prompt_order 展开
{{setvar/getvar}} 宏、一个条目一个开关、启用状态照搬，玩家开场页看得见每一条。你只要告诉他
"你的预设在开场页写法那一栏能选"。要用 `open_stage` 直接指定就传 `style: {preset: "user:<名>"}`。

**你自己代演时**，预设里的文风条目跟 `story-voice` 是同一个位置：拆出来写进 CLAUDE.md 台面规矩
之后，**它压过 story-voice 的目录表和系统提示词的缺省**。三层覆盖关系是
「系统提示词地板 < story-voice < 用户的 CLAUDE.md」，打架一律听 CLAUDE.md。

预设常见的结构（认出来就好拆）：一堆**开关条目**（每条往一个变量里塞一段文字）
加几条**总装条目**（把变量拼成最终提示词）。开关条目里没启用的那些是**备选功能**，
别丢 —— 见下面的处理物落盘。

# ⛔ 搬设定不搬引擎（大世界卡的一半是程序）

大型世界卡常驻条目里一半是**酒馆前端的引擎件**：MVU 变量系统、HTML 状态栏、
CoT 框架、自定义回复格式、`regex_scripts`、`tavern_helper`、marker 占位。
**这些一律不搬** —— 这个平台有自己的对应物：

| 酒馆的 | 我们的 |
|---|---|
| 变量 / 状态栏 | 状态板（`follow` 跟着最新章走） |
| 骰子插件 | `roll_dice` 真投 + 明骰表 |
| 跨会话状态 | `记忆/` |
| 可点选项 / 快捷回复 | `nd:controls` 围栏 |
| 世界书关键词触发 | `世界书/` + 你手上的 `Grep` |

判据一句话：**这条是给读者看的（搬），还是给酒馆程序执行的（不搬）。**
挑常驻进 CLAUDE.md 时逐条过这一刀。

# CLAUDE.md 骨架（往现成的节里填，不另立一套）

节名跟 rp 项目自带的「演出档案」模板是同一套（`workspace-templates.js` 是唯一
真相源）：

```markdown
# 演出档案
## 世界观锚      （常驻十条以内；其余在 世界书/ 按触发词取）
## 台面规矩      （文风禁令 / 叙事规则 / 骰子规则 / 想跟谁演·难度·代笔档）
## 人物          （每人三行核心 + 指路 角色/<名>/角色卡.md）
## 称呼与习惯    （用户扮演谁、怎么称呼；语气与节奏偏好）
```

改这份文件要用户点头。

# 处理物落盘，别用完就丢

消化完一份预设或大卡，把处理产物放进 `预设/<名>/`（桌面文件夹，用户随时取用、
随时改）：

- **`落点对账.md`** —— 每个条目去了哪：CLAUDE.md 哪一节 / 哪份人物档案 /
  哪个世界书文件 / 丢弃（写明为什么）。这是这份预设在本项目的地图。
- **`未启用条目.md`**（多了按主题拆）—— 没开的模式、备选文风、开关类条目**原文**
  留存。用户中途说「把那个吐槽模式打开」时，答案在这里，不用回头重啃原始 JSON。

原始文件躺 `assets/` 不动。这些处理物是**工作成果不是缓存** —— 换场、换玩法、
用户翻悔某条规则时，都从这里取。

# 用的时候（每拍动笔前的固定两拍）

1. 拿本拍要写的人名/地名/物件/事件 **grep `世界书/`**（触发词在 frontmatter keys
   和文件名里），命中就 Read 进来。**你手上的 Grep 就是酒馆的关键词触发器。**
   宁可多 grep 一个词，也别凭记忆编设定。
2. 写完过一眼状态板要不要更新（连同 reflow，就手做掉）。
